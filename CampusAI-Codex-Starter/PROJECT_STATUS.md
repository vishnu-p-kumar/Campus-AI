## Separate resume review from skill matching (2026-11-26)

- Root cause: the resume Analyze form required a role title and sent the resume and role in one `/resumes/analyze` request. `analyze_resume_text` generated a `role_comparison`, and the API persisted that as a SkillGapAnalysis row. The frontend displayed both outputs together, despite separate histories.

Latest and resume history responses no longer embed a role comparison. This prevents older clients' extra role fields from triggering skill matching as well.
- Updated the user guide and regression tests to assert that Analyze does not make a comparison request or return/save skill-gap output.
